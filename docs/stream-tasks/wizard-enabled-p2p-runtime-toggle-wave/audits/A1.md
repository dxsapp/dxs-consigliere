# wizard-enabled-p2p-runtime-toggle — A1 audit

First audit cycle after initial execution. Branch
`codex/consigliere-vnext`. Range `3e78b2c..01ac6f3`.

## What landed

### S1 — runtime-settings doc + seed + wizard write (`34ecce0`)
`OperatorRuntimeSettingsDocument` (RavenDB, nullable `P2pEnabled`) +
`IOperatorRuntimeSettingsStore` (thin Raven) + `OperatorRuntimeSettingsService`
(`GetP2pEnabledAsync = doc?.P2pEnabled ?? BsvP2pConfig.Enabled`;
`SetP2pEnabledAsync`). `SetupWizardService.CompleteAsync` writes
`P2pEnabled=true`. DI in `IndexerStateSetup`. The nucleus of a future
"runtime settings in the DB" model — operational toggles only, no secrets.

### S2 — supervisor + live toggle (`01ac6f3`)
`BsvP2pHostedService` is now a supervisor: effective-enabled = DB ?? config
seed; brings the peer pool up/down at runtime; watches the settings doc via
the RavenDB Changes API so the wizard write flips the thin node on live, no
restart. `DecideAction` pure + unit-tested (idempotent, CI-safe-off).
Serialized by a SemaphoreSlim (acquire-flag release; state re-read in-lock).
`P2pMempoolIngestRunner` made pool-readiness-driven (keys off
`BsvP2pHealth.Bound`; lazy watchlist load on first bound tick; clears stale
wirings on pool drop), so it activates with the pool and does zero Raven work
when P2P is off.

## Residuals
- **Live pool start/stop unverified (evidence-pending).** The actual peer-pool
  bring-up/teardown needs real network I/O — unit coverage is the pure
  decision + idempotency, not the wire. The end-to-end proof (fresh Local
  stack, P2P off → complete wizard → `BsvP2pHealth.Bound` true, peers
  connecting, no restart) is operator-run.
- **Changes-connection resilience.** If the RavenDB changes connection drops
  mid-run, the live toggle is silently disabled until restart (the
  subscription is not re-established). The boot-time state still applies. Worth
  a follow-up if operators rely on frequent runtime toggles. (Flagged for the
  S2 audit.)
- **mainnet-guard behaviour change.** A non-mainnet config now logs an error +
  leaves the pool down instead of throwing at startup — a misconfigured/
  disabled subsystem cannot crash the host. Intentional; called out for audit.
- **`BsvP2pConfig.Enabled` default stays false.** Base appsettings is
  unchanged; the wizard (DB override) is what turns P2P on for real
  deployments. The turnkey Local profile could additionally set the seed true,
  but that's not required now (the wizard handles it) and was left out of scope.
