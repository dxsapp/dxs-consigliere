## Per-slice validation

### S0 — TLS termination + cookie Secure

- Caddy 2 in `compose.yml` (dev profile) + `compose.prod.yml`
  override (prod profile). `tls internal` in dev, ACME via
  `${CADDY_DOMAIN}` + `${CADDY_EMAIL}` in prod.
- Cookie `SecurePolicy` config-driven via
  `Consigliere:AdminAuth:cookieSecure`; conservative parser
  maps unknown → `Always`.
- `app.UseForwardedHeaders()` wired BEFORE `UseCors` /
  `UseRouting`.
- 13/13 backend unit tests (forwarded-headers + cookie
  parser).
- S0 fold closed M1 (`--profile dev config` no longer
  fails on prod env interpolation), M2 (dev TLS handshake),
  L1 (ledger hash drift), L2 (runbook env-var lie about
  `IList<IPAddress>`).

### S2 — Health endpoints

- `/health/{live,ready,startup}` anonymous probes with
  named tag predicates; `LogStreamBuffer`-style fan-out
  doesn't apply (these are stateless on the request side).
- Probes opted out of the S1 rate limiter via
  `.DisableRateLimiting()` chained on every
  `MapHealthChecks(...)`.
- 11/11 backend unit (was 9; +2 after the S2 fold) + 4 contract
  describes. `RavenHealthCheck`, `ProviderReachabilityCheck`,
  `StartupDiCheck` + shared JSON `HealthResponseWriter`.
- S2 fold closed M1: `ProviderReachabilityCheck` keys on
  `IAdminProviderConfigService.GetEffectiveSourcesConfigAsync()`
  + honours `Enabled` flag; degrades gracefully when
  effective-config retrieval throws.

### S1 — Rate limiting on auth + broadcast

- Three IP-keyed fixed-window policies — `login` 5/min,
  `me` 100/min, `broadcast` 1/sec.
- Conservative defaults from `RateLimitingConfig`;
  overridable via `RateLimiting:*` env vars.
- `[EnableRateLimiting("login")]` / `("me")` / `("broadcast")`
  on the load-bearing controller methods; health
  endpoints opted out.
- Admin UI `ApiClient` honours `Retry-After` exactly once
  (clamped to 65s) then throws `RateLimited` AppError.
- 6 backend unit + 4 frontend unit + 3 contract burst
  describes (5+5 cutoff with `Retry-After` on every 429).
- **Cleanest audit verdict in the wave: APPROVE with 0
  findings.**

### S5 — Secrets at rest

- `SecretsFileStore` replaces the Raven-backed
  `RealtimeSourcePolicyOverrideStore` (deleted).
  Atomic-write tmp + `Move(overwrite:true)`; chmod 600 on
  POSIX.
- `MigrateFromRavenAsync` is the one-shot wave-A2 → A3
  cutover, fail-stop in `Startup.InitializeDatabase`.
- `appsettings.Production.json` lands with `${ENV_VAR}`
  placeholders; `compose.yml` mounts the
  `consigliere-secrets` named volume; `Consigliere__Secrets__Dir`
  env points at it.
- `scripts/secrets-lint.sh` + new CI job grep-gate
  `appsettings*.json` for plaintext credentials.
- 6 unit + 4 RavenTestDriver migration tests.
- S5 fold closed M1 (migration re-checks Raven on every
  startup so a prior partial migration retries until the
  Raven doc is actually gone) + L1 (CI installs both
  .NET 8 + .NET 9 so the migration `SkippableFact`s
  actually execute remotely).

### S3 — Audit log for destructive operations

- `AuditLogEntry` Raven document (immutable;
  `UpdateableKeys() == EmptyKeys`); 365-day `@expires`
  metadata.
- `IAuditLogger.RecordAsync → Task<bool>`; `BroadcastService`
  fail-stops with `audit_write_failed` when the record
  fails.
- `AdminAuditController` admin-authed read endpoint with
  `since|action|username|lastN` filters + 1000-row hard
  ceiling.
- Admin UI `/audit-log` MUI DataGrid + filter chips +
  JSON-context modal.
- 11/11 backend unit (8 broadcast behavior + 3 audit-
  logger after S3 fold) + 5 store + 3 mock + 1 contract.
- S3 fold closed M1 (`AuditLogger` fail-stops when
  `ConfigureExpirationOperation` fails — split into
  `IAuditRetentionConfigurator` for testability) + L1
  (`MockAdminClient.broadcastRaw` prepends a freshly-
  stamped audit entry so the mock-mode smoke is a real
  round-trip).

### S4 — Backend log streaming

- `LogStreamBuffer` (1000-entry ring, drop-oldest on

- `LogStreamProvider` MEL `ILoggerProvider` captures

- Admin UI `LogsPage` rewritten as live tail; the

- 12 backend unit (sanitizer + buffer) + 5 logs.store

## Behavioral summary

The Consigliere admin surface that entered wave-A3 had no
HTTPS termination, no rate limiting, no health probes, no
audit trail, no live log view, and shipped its provider
secrets as plaintext inside a RavenDB document. The surface
that exits wave-A3 has all six, plus a Swashbuckle NRT-aware
type tightener that lets future TS surface migrate onto
generated types incrementally without losing tightness, and
a single operator-facing handbook (`docs/runbook.md`) that
encodes every operational procedure end-to-end.

The wave's 8 slices, 5 fold cycles, 16 audit findings (3
H/M/L from S0 + 1 M from S2 + 0 from S1 + 2 from S5 + 2 from
S3 + 1 from S4 + 1 from S6), and 24/24 green admin-ui
contract suite at every step represent the kind of
disciplined audit-then-fold cadence the wave-A2 closeout
called out as the right pattern for this codebase. Nothing
shipped without a verdict; nothing remained open across more
than one audit cycle.
