## Residuals
- **Cold-start P2P warm-up window (honest).** `p2p` is the default
  realtime + rawTx primary, but a fresh host's peer pool takes time to warm
  (UA filtering; Gate-2 soak not fully green per project memory). Mitigated
  by design: external realtime runners run **always** (S3) so ingest never
  stalls, and rawTx misses auto-fall-back to external (S2). The first-seen
  metric (S4) will show p2p lagging until the pool warms.
- **Routing/subsystem gate decoupling.** `p2p` routability is gated on
  `Providers.P2p.Enabled` (default true), independent of the P2P subsystem
  master switch `BsvP2pConfig.Enabled` (default false). When the subsystem
  is off, routing still lists p2p primary but every fetch finds no peers →
  fast null → external fallback (safe, slightly wasteful). To actually RUN
  the thin node, an operator/profile must set `BsvP2pConfig.Enabled=true`
  (e.g. the turnkey Local profile). Flagged for S1 audit as a possible Low.
- **Live end-to-end unverified.** Real mainnet p2p getdata hit + first-seen
  race vs external is operator-run evidence-pending (needs a live peer pool
  + mainnet mempool). Code paths + unit coverage are in place.
