# S0 Audit A1 — Program-Wide Contract Freeze

Verdict: **MAJOR REVISION REQUIRED**

## Findings

1. **H1 — `SendGetHeadersAsync` return type does not match the frozen S0 spec**

   **Where:** `docs/stream-tasks/bsv-headers-chain-wave/slices.md:42-50`; `src/Dxs.Bsv/P2p/Session/PeerSession.cs:212-221`; `tests/Dxs.Consigliere.Tests/P2p/ContractFreeze/manifest.json:55-68`; `tests/Dxs.Consigliere.Tests/P2p/ContractFreeze/ContractFreezeApprovalTests.cs:45-53`, `tests/Dxs.Consigliere.Tests/P2p/ContractFreeze/ContractFreezeApprovalTests.cs:230-246`.

   **Evidence:** S0.2 specifies `Task SendGetHeadersAsync(GetHeadersMessage msg, CancellationToken ct)` (`slices.md:46`). The implementation adds `public ValueTask SendGetHeadersAsync(GetHeadersMessage msg, CancellationToken ct)` (`PeerSession.cs:216`). The manifest then freezes the implementation shape as `System.Threading.Tasks.ValueTask` (`manifest.json:55-68`), and the approval test compares reflected return types against that manifest (`ContractFreezeApprovalTests.cs:230-246`).

   **Why it matters:** This is the exact class of silent contract drift S0 is supposed to prevent. Downstream slices can probably `await` either `Task` or `ValueTask`, but the frozen surface is no longer the surface approved in `slices.md`. If S1-S7 open now, later correction requires a contract-freeze amendment instead of a simple S0 fix.

   **Recommendation:** Before opening S1-S7, make the frozen contract internally consistent. Either change `PeerSession.SendGetHeadersAsync` to return `Task` and update the manifest accordingly, or explicitly amend `slices.md` §S0.2 to freeze `ValueTask` because it matches the existing `PeerSession` send-helper pattern, then keep the current implementation and manifest. Re-run `ContractFreezeApprovalTests` after the chosen correction.

2. **M1 — The documented grep validation is impossible to pass as written**

   **Where:** `docs/stream-tasks/bsv-headers-chain-wave/slices.md:288-305`; `docs/stream-tasks/bsv-headers-chain-wave/slices.md:20-29`; `docs/stream-tasks/bsv-headers-chain-wave/audits/wave1-audit-A1.md:17-25`, `docs/stream-tasks/bsv-headers-chain-wave/audits/wave1-audit-A1-followup.md:19-27`.

   **Evidence:** S0 validation says to grep across `src/` and `docs/` for `OnBlockInvReceived` or `OnInvReceived(tx)` and require zero hits (`slices.md:297-299`). The wave docs and prior audits intentionally contain those exact strings while documenting the old split and its closure (`slices.md:24-28`, prior audit references above). A literal `rg` over `src tests docs/stream-tasks/bsv-headers-chain-wave` returns these documentation hits even though no implementation leftovers were found.

   **Why it matters:** The static check can fail for documentation-only historical references, creating a false blocker during S0 closeout. It also weakens the audit trail because operators have to decide ad hoc which matches count.

   **Recommendation:** Scope the check to production/test code, e.g. `rg -n "OnBlockInvReceived|OnInvReceived\\(tx\\)" src tests`, or keep docs in scope but exclude `docs/stream-tasks/bsv-headers-chain-wave/audits/` and the explanatory S0 lines. Record the exact command in S0 evidence.

## Checks Performed

- S0 member coverage: the callback properties, telemetry types, hub DTOs, hub subscription methods, and `BroadcastReceiptDto` freeze are present. The only spec/signature mismatch found is `SendGetHeadersAsync` return type.
- Additive dispatch: `PeerSession.ReceiveLoopAsync` parses `headers`, `inv`, and `reject`, invokes callbacks, then uses `break` so execution reaches the channel write at `PeerSession.cs:347-350`; it does not `continue` for those commands.
- Telemetry: `PeerTelemetry` preserves `RejectByClass` as `IReadOnlyDictionary<RejectClass,long>`, includes getdata p50/p95 latency, relay-back inv count, and protocol-violation count (`PeerTelemetry.cs:18-33`). `IPeerTelemetrySink` takes rich events with `InvType`, per-hash spans, per-class rejects, and serve latency (`IPeerTelemetrySink.cs:23-34`).
- Relay telemetry: `TxRelayCoordinator` calls `session.Telemetry` directly on the session that emitted the frame; getdata requested is recorded before serving, getdata served after `SendTxAsync` with measured latency, and relay-back invs are recorded on matching `inv` frames (`TxRelayCoordinator.cs:93-150`).
- SignalR split: `OnNewBlock` / `OnReorg` are only on `IWalletHub`; `SubscribeToBlockTip` / `SubscribeToReorg` are on `IWalletServer` and implemented in `WalletHub`; `WalletHub` does not expose `OnNewBlock` / `OnReorg` server methods.
- Guardrails: commit `c7b1428` does not touch `src/Dxs.Bsv/P2p/Pool/PeerManager.cs`, and the changed file list contains no header-chain logic, Raven header document/store, or hosted-service implementation.
