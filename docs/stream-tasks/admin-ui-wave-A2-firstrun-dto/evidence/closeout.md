# Wave A2 — closeout

## Result

Wave A2 ships the chicken-and-egg first-run UX fix + a
two-layer DTO safety net (compile-time drift gate + runtime
parity gate) against the live backend. Operators no longer
hand-type curl payloads to install Consigliere; backend wave
authors no longer have to remember to update TS DTOs by
hand — both gates fire red on drift, with the runtime
gate catching the cases the compile-time gate misses.

## Behavioural summary

Before:
- A first-time operator landed on `/login` with a cryptic
  `{"code":"setup_required"}` error after submit. The only
  documented install path was a multi-step curl POST to
  `/api/setup/complete`.
- TS DTOs were hand-mirrored from C#. Two drift cases
  shipped in wave-A1 (caught only in retroactive audits).

After:
- A fresh visit to `/` from a clean install lands directly
  on `/setup`. Four MUI Stepper steps walk the operator
  through admin account + provider routing + JungleBus
  block sync. Submit creates the admin account + signs the
  operator in.
- Every backend DTO change that touches the wire shape
  fails CI red — either at `pnpm contracts:check` (S1
  compile-time gate) or at `pnpm test:contract` (S2
  runtime gate against real responses).

## Contract parity evidence

Wave-A1 audit H1 (TrackedHistoryStatusResponse drift) +
H2 (AdminTrackedTokenBalanceSummaryResponse drift) would
each have been caught by this wave's gates:

- **S1 gate**: a backend property rename produces a non-zero
  diff in `api.generated.ts`. `pnpm contracts:check` exits
  1 with a tight `git diff --unified=3` hunk.
- **S2 gate**: a backend response that doesn't match the
  declared schema (e.g. `tokenBalances[*].satoshis` removed
  + replaced with `balanceSatoshis`) fails the
  `expectShape("AdminTrackedAddressResponse", body)` ajv
  call in the `tracked/addresses` describe with a precise
  field-level error path.

## Accepted design deviations

None this wave — Swashbuckle's default emitter shape (`?:`
on every property, no `required` array) is the only
behaviour that intentionally diverges from what a strict
ajv-based gate would want. Documented as wave-A3 residual.

## Residuals → next wave

- **Swashbuckle NRT-aware required-field inference**
  (wave-A3 S?) — adds a swagger gen filter that walks
  nullable annotations on each C# DTO and populates the
  OpenAPI `required` arrays. Then the screens can finally
  switch off the hand-mirrored interfaces in
  `types/admin.ts` + `types/auth.ts`.
- **S2 codex audit + fold** — runs after this closeout.
- **Write-side contract parity** (wave-A4) — exercise
  `POST /api/tx/broadcast` against the real backend.
- **`appsettings.Test.json` background-task disable
  semantics** (wave-A3 cleanup) — switch from
  `EnabledTasks: []` (which doesn't clear inherited
  values) to a `DisableAll: bool` knob on
  `BackgroundTasksConfig`.

## Open assumptions

- Cookie auth stays the canonical session model
  (unchanged from wave-A1).
- RavenDB stays as the authoritative store; the contract

  CI run.
- Swashbuckle 9.x's OpenAPI 3.0 emitter shape is stable
  enough that wave-A3's NRT filter can drop in without a
  separate swagger spec rewrite.
