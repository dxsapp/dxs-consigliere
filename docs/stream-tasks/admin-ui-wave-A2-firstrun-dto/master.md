# Admin UI Wave A2 — First-run UX + DTO safety

Wave-A2 closes the two highest-friction residuals from
wave-A1: operators can't install Consigliere without a
hand-typed `curl POST /api/setup/complete`, and the
TS-vs-C# DTO mirror is hand-maintained — wave-A1 found and
fixed two drift cases inside 2 audits, proving that "trust
the reviewer" is not a CI gate.

## Goal

A first-time operator can install Consigliere, open
`http://<host>:5000`, complete the first-run wizard
**from the UI**, and reach the admin shell — with zero curl
invocations + zero documentation outside the form itself.

In parallel, every TS DTO under `src/admin-ui/src/types/`
that mirrors a C# DTO is **generated** from a backend
`/swagger.json` artifact, and a CI gate fails the build the
moment a backend rename, field addition, or nullability
change is not reflected in the regenerated TS.

Business outcome:
- Removes the longest-tail onboarding step (the curl).
- Removes a recurring class of bugs (wave-A1 audit H1 +
  H2 were both DTO drift), which translates to fewer
  hotfixes after backend waves.

## Product Decision

- **`/setup` is a public route** rendered outside
  `AuthGuard`. The route only mounts when the backend
  reports `setupRequired: true OR setupCompleted: false`
  from `GET /api/setup/status`; once setup is done it
  redirects to `/login`.
- **Four-step wizard, not single-screen form.** Matches the
  shape of `POST /api/setup/complete`:
  1. **Admin account** — username + password + confirm.
  2. **Providers** — primary realtime / rawTx / REST +
     Bitails transport + per-provider URLs/keys.
  3. **Block sync** — JungleBus base URL + subscription
     ID (required).
  4. **Review + confirm** — diff view of the assembled
     payload, confirm button.
- **Bring up the wizard from `GET /api/setup/options`.**
  The backend already exposes defaults + allowed values.
  The wizard pre-fills the form from `options.defaults`
  + `options.providerConfig`; validation lives on the
  client (required fields, URL shape, hex character class).
- **No backend changes for S0.** The setup endpoint
  contract is already there. S0 is purely UI work + tests.
- **Swagger codegen targets `src/admin-ui/src/types/
  api.generated.ts`.** Hand-mirrored types under
  `types/admin.ts` and `types/auth.ts` continue to type
  domain helpers, store contracts, and mocks. The generated
  file is the source of truth for **wire shapes**.
- **Refactor to re-export from `api.generated.ts` is
  deferred** — wave-A2 S1 closeout call (see Residuals
  below). Swashbuckle's default emitter marks every property
  as optional (`?:`); switching screens onto the generated
  types would cascade `T | undefined` handling into 30+
  screen files without a real defect to fix. The drift
  GATE still catches every backend DTO change — a rename or
  shape change produces a non-zero diff in
  `api.generated.ts` and CI fails red. Tightening the
  generated types via Swashbuckle NRT-aware required-field
  inference is a wave-A3 residual.
- **The contract-parity test (S2) is owned by the
  `verification-and-conformance` zone.** It boots the real
  ASP.NET host on a random port (env-injected
  `DOTNET_ENVIRONMENT=Test`), hits every admin endpoint
  with seed data, and validates the response against the
  generated TS types via a runtime type-guard. No mock
  layer in this test.
- **No new backend DTOs.** This wave only mirrors what
  exists at HEAD `c4d50ce`. New backend endpoints from
  future waves regenerate types through the same gate.

## Scope

In scope:
- New `/setup` route + wizard + per-step validation
- `SetupWizardStore` (MobX, follows wave-A1 detail-store
  pattern)
- Backend `--emit-swagger` build flag (writes
  `swagger.json` to repo root or a CI-uploadable artifact)
- `pnpm contracts:generate` + `pnpm contracts:check`
  scripts (already documented in
  `src/admin-ui/contracts/README.md` as wave-A1 residual)
- `src/admin-ui/src/types/api.generated.ts` checked-in,
  generated by `openapi-typescript`
- Un-skip `src/admin-ui/tests/contract/auth.test.ts` +
  add full coverage for the admin endpoint surface
- CI workflow extension: a `admin-ui-contracts` job that
  runs `pnpm contracts:check` and the parity test against
  a freshly built backend

Out of scope:
- HTTPS / TLS — owned by wave-A3
- Rate limiting on auth endpoints — wave-A3
- Audit log of destructive operations — wave-A3
- Multi-user RBAC — wave-A5
- Write-mode `/configuration` — wave-A5
- Deleting the hand-mirrored DTOs — deferred until wave-A2
  has soaked through one full backend wave without
  regressions (target: wave-A3 closeout)

## Core Rules

1. **No backend DTO mutation in this wave.** Wave-A1 Core
   Rule §10 still applies. Any new endpoint or shape change
   is a separate slice in a separate wave.
2. **The wizard mirrors `SetupCompleteRequest` exactly.**
   No fields renamed, no fields added, no fields silently
   dropped. If the backend adds a future field, the wizard
   form goes via the standard slice-audit pattern.
3. **`api.generated.ts` is generated, never edited by
   hand.** A pre-commit hook (or at minimum a
   `pnpm contracts:check` step in `pnpm verify`) protects
   the file.
4. **The parity test boots a real backend.** No mocks.
   Test failures must point at the C# DTO that drifted, not
   at a TS-side stub.
5. **No back-compat shims for the old curl path.** Once
   the wizard ships, `POST /api/setup/complete` is reachable
   from the UI exclusively. The endpoint stays public +
   anonymous (already is) so an automated installer could
   still drive it, but UI docs route operators to the form.
6. **Loud failure on backend incompat.** If
   `pnpm contracts:check` finds drift OR the parity test
   sees a missing field, CI fails red. No silent recovery,
   no auto-regenerate.

## Definition of Done

- All 3 slices `done`; each has a corresponding
  `audits/S<n>-slice-audit-followup.md` with verdict
  `APPROVE` or `APPROVE WITH CHANGES (folded)`.
- `pnpm verify` chain ends with `pnpm contracts:check`
  AND `pnpm inventory` AND `pnpm budget` — all gates green.
- New CI job `admin-ui-contracts` runs on every PR + main
  push, fails red on drift.
- A fresh `docker compose up --build` against a clean
  RavenDB volume lands the operator on `/setup` (NOT on
  `/login`), the wizard completes, and the operator is
  signed in.
- Wave audit (`audits/A1.md`) records the closeout
  evidence: validation commands, per-slice commit hashes,
  CI run links, before/after install-flow screenshots,
  measured backend swagger size, generated TS size delta.
- `evidence/closeout.md` written per playbook template.
- Updated `docs/stream-tasks/admin-ui-vnext-program/
  evidence/closeout.md` notes wave-A2 closed the
  "Swagger codegen + ASP.NET-host parity test" residual.
