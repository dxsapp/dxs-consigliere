## Audit dimensions

Score each finding **CRITICAL** / **HIGH** / **MEDIUM** /
**LOW**.

### Backend safety

1. **Swagger UI surface.** `app.UseSwaggerUI()` runs only
   when `!env.IsProduction()`. Verify a production
   deployment (`DOTNET_ENVIRONMENT=Production`) does NOT
   expose `/swagger` UI. The middleware itself
   (`app.UseSwagger()`) stays so the parity test in S2 can
   GET `/swagger/v1/swagger.json`.
2. **`--emit-swagger` doesn't run hosted services.** The
   emit branch builds the host but never calls
   `app.RunAsync()` or `InitializeDatabaseWithRetryAsync`.
   No background task starts, no Raven migration runs.
   Verify by reading `Program.cs` — the branch returns
   before the regular host startup.
3. **`--emit-swagger` exit codes.** Returns 0 on success,
   1 on emit exception, 2 on missing path argument. The
   regular happy-path also returns 0 (was previously
   implicit). Flag if any code path leaves stderr unprinted
   on failure.
4. **Output path resolution.** The script accepts an
   absolute or relative path. Relative paths resolve
   against `Directory.GetCurrentDirectory()` (which is
   the project directory when invoked via
   `dotnet run --project ...`). `contracts-generate.mjs`
   passes absolute paths to avoid the ambiguity that bit
   the initial dev run.
5. **Output directory creation.** The emit code calls
   `Directory.CreateDirectory(dir)` before writing.
   Confirm a write to a deep path (e.g.
   `/tmp/foo/bar/swagger.json`) succeeds without
   pre-creating the parent.

### Codegen pipeline correctness

6. **`contracts-generate.mjs` pipeline ordering.** Stage 1
   (`dotnet run --emit-swagger`) must complete with exit
   code 0 before stage 2 (`openapi-typescript`) runs. A
   non-zero from stage 1 → script exits with the same
   code; stage 2 is skipped.
7. **`SWAGGER_OUT` + `TYPES_OUT` env overrides.** The
   script reads `process.env.SWAGGER_OUT` /
   `process.env.TYPES_OUT` for CI flexibility. Verify the
   defaults resolve to `contracts/swagger.json` +
   `src/types/api.generated.ts` relative to the admin-ui
   root, not the cwd.
8. **`pnpm exec openapi-typescript` invocation.** Uses
   `process.env.npm_execpath ?? "pnpm"`. Spot-check that
   running the script via a pure-Node invocation (no
   `pnpm run` wrapper) still resolves the binary via
   `pnpm exec`. Flag if the npm_execpath fallback could
   fail under yarn / npm CIs.
9. **`contracts-check.mjs` hermeticity.** Regenerates into
   `mkdtempSync(tmpdir())` + cleans up in `finally`. No
   writes to the working tree on either path. Verify the
   `rmSync(..., { recursive: true, force: true })` runs
   even when the diff path returns early.
10. **Diff output usefulness.** On drift, the script emits
    a `@<line>` + `-old`/`+new` unified-ish diff capped at
    60 entries. Flag whether 60 is enough for realistic
    backend renames (e.g. a property rename in
    `BroadcastReceiptDto` would touch ~3 lines; a model
    rename like `P2pHealthDto` → `BsvHealthDto` could
    touch dozens via `paths.{}.content` refs).

### Drift gate semantics

11. **Drift simulation.** Manually injecting a one-line
    edit into `api.generated.ts` and running
    `pnpm contracts:check` exits 1 with the edited line
    in the diff. Verified during S1 dev:
    `// DRIFT TEST` line → exit 1 → restore → exit 0.
12. **What the gate catches.** A backend DTO rename, a
    field addition, a nullability change, or a property
    removal all surface as a non-zero diff. Flag if a
    semantic change (e.g. JSON wire format change without
    schema change — `JsonStringEnumConverter` flipping)
    could bypass the gate.
13. **What the gate misses.** Hand-mirrored types in
    `types/admin.ts` are not refactored (intentional —
    documented in master.md scope notes). A backend
    rename therefore changes `api.generated.ts` (gate
    fires) but does NOT cause TS errors in screen code
    (screens still compile against the stale hand-
    mirrored interface). Confirm the master.md residuals
    section captures this as a wave-A3 followup.
14. **First-run install of the drift gate.** A developer
    who deletes `contracts/swagger.json` + `api.generated.ts`
    and runs `pnpm contracts:generate` reproduces the
    committed files byte-identically. Flag any
    non-determinism (openapi-typescript ordering,
    Swashbuckle schema ID stability across builds).

### CI integration

15. **`pnpm verify` chain.** Now ends with
    `pnpm contracts:check`. Order:
    `typecheck → lint → test → build → budget → inventory
    → contracts:check`. Verify a CI run that already
    passes everything else but has DTO drift fails red on
    the last step.
16. **`actions/setup-dotnet@v4`.** Pinned at `9.0.x` to
    match the backend job. The admin-ui CI job needs it
    because `contracts:check` spawns `dotnet run`.
17. **`dotnet restore` warmup step.** The CI workflow
    runs `dotnet restore ./Dxs.Consigliere.sln` BEFORE
    `pnpm install` so the first `dotnet run` inside
    `pnpm contracts:check` doesn't pay the restore tax
    inside the verify wall-clock budget.
18. **`working-directory: .` override on the restore
    step.** The job's default cwd is `src/admin-ui`; the
    restore step overrides to the repo root. Spot-check
    the cwd override syntax is correct on `runs:`.
19. **Timeout bump.** Job timeout was 15 min; bumped to
    20. Flag if 20 min is enough for a worst-case dotnet
    cold + Playwright e2e run combined (e2e runs in a
    separate job, so this only covers `pnpm verify`).
20. **e2e job not impacted.** The `admin-ui-e2e` job does
    NOT need dotnet (mock-mode dev server). Spot-check
    that no new dependency leaked into that job's steps.
